backoff-kit

A small TypeScript library for retrying async calls with exponential backoff and jitter. Zero dependencies, works in Node 18+, Deno, Bun and browsers.

Install

npm install backoff-kit
pnpm add backoff-kit
yarn add backoff-kit
bun add backoff-kit

The package ships ESM and CommonJS builds with bundled type declarations.

Quick start

import { retry } from "backoff-kit";

const user = await retry(async () => {
  const res = await fetch("https://api.example.com/users/42");
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
});

With no options, retry calls your function up to 6 times (the first attempt plus 5 retries). It waits between attempts with exponential backoff and full jitter, and resolves with the first successful result. If every attempt fails, it rejects with the last error.

Pass options as the second argument:

const data = await retry(() => loadReport(), {
  retries: 3,
  minDelay: 200,
  maxDelay: 5_000,
  onRetry: ({ attempt, delay, error }) =>
    console.warn(`attempt ${attempt} failed, retrying in ${delay}ms`, error),
});

retry(fn, options)

function retry<T>(
  fn: (ctx: AttemptContext) => Promise<T> | T,
  options?: RetryOptions,
): Promise<T>;

interface AttemptContext {
  attempt: number;      // 1 for the first call, 2 for the first retry, ...
  signal?: AbortSignal; // the signal you passed in options, if any
}

fn may be sync or async. It receives an AttemptContext, which you can ignore or use to forward the abort signal into fetch. Any thrown error or rejected promise counts as a failed attempt.

Options

OptionTypeDefaultDescription
retriesnumber5Maximum number of retries after the first attempt. 0 calls fn once with no retry.
minDelaynumber (ms)100Delay before the first retry, before jitter.
maxDelaynumber (ms)30000Upper bound for any single delay.
factornumber2Multiplier applied to the delay after each retry.
jitter"full" | "equal" | "none" | (delay: number) => number"full"How randomness is applied to each delay. See How delays work. A function receives the capped delay and returns the final one.
shouldRetry(error: unknown, attempt: number) => boolean | number | Promise<boolean | number>retry every errorDecides whether a failure is retried. Return false to stop and reject with that error. Return a number to retry after exactly that many ms, skipping the computed delay (useful for Retry-After).
onRetry(info: { error: unknown; attempt: number; delay: number }) => voidnoneCalled before each wait. attempt is the attempt that just failed. Use it for logging or metrics.
signalAbortSignalnoneCancels the operation, including any wait in progress. See Aborting.

How delays work

Before retry n (starting at 1), the capped delay is:

capped = min(maxDelay, minDelay * factor ^ (n - 1))

Jitter then spreads that value so many clients that failed together don't all retry together:

  • "full": random value in [0, capped]. Best at spreading load.
  • "equal": capped / 2 plus a random value in [0, capped / 2]. Keeps a guaranteed minimum wait.
  • "none": exactly capped. Predictable, handy in tests.

Try it. Each bar shows the range a delay can fall in, with the cap marked.

Errors

  • When retries are exhausted, retry rejects with the error from the last attempt, unchanged.
  • When shouldRetry returns false, retry rejects immediately with that error.
  • When signal aborts, retry rejects with signal.reason (a DOMException named AbortError by default).

Recipe: HTTP 429 handling

Retry rate-limit and transient server errors, and respect the server's Retry-After header when present. Returning a number from shouldRetry overrides the computed delay.

import { retry } from "backoff-kit";

class HttpError extends Error {
  constructor(readonly status: number, readonly retryAfter?: string | null) {
    super(`HTTP ${status}`);
  }
}

function retryAfterMs(value?: string | null): number | undefined {
  if (!value) return undefined;
  const seconds = Number(value);
  if (!Number.isNaN(seconds)) return seconds * 1000;
  const date = Date.parse(value);
  return Number.isNaN(date) ? undefined : Math.max(0, date - Date.now());
}

const res = await retry(
  async () => {
    const r = await fetch("https://api.example.com/items");
    if (!r.ok) throw new HttpError(r.status, r.headers.get("retry-after"));
    return r;
  },
  {
    retries: 6,
    shouldRetry: (err) => {
      if (!(err instanceof HttpError)) return true;          // network error
      if (err.status === 429) return retryAfterMs(err.retryAfter) ?? true;
      return err.status >= 500;                              // 5xx only
    },
  },
);
Cap server-provided waits yourself if you don't trust them, for example Math.min(ms, 60_000). A numeric return value is used as-is.

Recipe: aborting with AbortSignal

Pass a signal to cancel from outside. Aborting stops the current wait immediately and no further attempts start. Forward the same signal into fetch so an in-flight request is cancelled too.

const controller = new AbortController();
cancelButton.onclick = () => controller.abort();

try {
  const data = await retry(
    ({ signal }) => fetch("/api/search?q=backoff", { signal }).then((r) => r.json()),
    { signal: controller.signal },
  );
} catch (err) {
  if (err instanceof DOMException && err.name === "AbortError") {
    // user cancelled
  } else {
    throw err;
  }
}

For an overall deadline, use AbortSignal.timeout:

await retry(() => syncJob(), { signal: AbortSignal.timeout(30_000) });

Recipe: custom retry predicates

By default every error is retried. Use shouldRetry to give up early on errors that will never succeed, such as validation failures, and to cap by attempt.

import { retry } from "backoff-kit";

const NON_RETRYABLE = new Set(["EINVAL", "EACCES", "ENOENT"]);

await retry(() => writeSnapshot(), {
  shouldRetry: (err, attempt) => {
    const code = (err as NodeJS.ErrnoException).code;
    if (code && NON_RETRYABLE.has(code)) return false;
    return attempt < 4; // stop after 4 failed attempts even though retries allows more
  },
});

The predicate may be async, for example to refresh a token before deciding:

await retry(() => callApi(token), {
  shouldRetry: async (err) => {
    if (err instanceof HttpError && err.status === 401) {
      token = await refreshToken();
      return true;
    }
    return false;
  },
});
