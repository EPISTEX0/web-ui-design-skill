backoff-kit

Retry async calls with exponential backoff and jitter. One function, retry(fn, options), written in TypeScript.

Quick start

Wrap the call that can fail in a function and pass it to retry. If the function throws or rejects, retry waits and calls it again. It resolves with the first successful result.

fetch only rejects on network failure, so the example throws on a bad status itself. Anything fn throws counts as a failed attempt.

How the delay works

Before retry number n (counting from 0), retry computes a ceiling, then applies jitter to it.

API reference

retry(fn, options)

Calls fn until it resolves, you stop it, or the retries run out.

fn receives a context object. Use ctx.attempt for logging and pass ctx.signal to anything that accepts an AbortSignal, such as fetch. All options are optional. These are the defaults, written out:

Options

retries

Type numberDefault 5

How many times to retry after the first call. retries: 5 means at most 6 calls in total. Use 0 to call fn once with no retries.

minDelay

Type number, millisecondsDefault 100

The ceiling for the wait before the first retry. Each later retry multiplies it by factor.

maxDelay

Type number, millisecondsDefault 30_000

The largest ceiling a retry can have. It caps the computed delay before jitter is applied. A number returned from shouldRetry is used as is and is not capped.

factor

Type numberDefault 2

The multiplier applied for each further retry. 2 doubles the ceiling every time. 1 keeps it constant.

jitter

Type 'full' | 'equal' | 'none'Default 'full'

How much randomness to apply to the ceiling.

  • 'full' waits a random time between 0 and the ceiling.
  • 'equal' waits half the ceiling, plus a random time up to the other half.
  • 'none' waits exactly the ceiling.

Keep jitter on when many clients may fail at once. Without it they all retry at the same moments and hit the service together.

signal

Type AbortSignalDefault none

Stops the retry loop. When the signal aborts, retry cancels any wait in progress, makes no further calls, and rejects with signal.reason. A signal that is already aborted rejects before the first call. The same signal is passed to fn as ctx.signal.

shouldRetry

Type (error: unknown, attempt: number) => boolean | numberDefault retries every error

Decides what to do after a failed attempt. attempt is 0 for the first call.

  • Return true to retry after the computed delay.
  • Return false to stop. retry rejects with this error.
  • Return a number to retry after that many milliseconds instead of the computed delay.

onRetry

Type (info: { error: unknown; attempt: number; delay: number }) => voidDefault none

Called once the delay is known and before retry waits, so you can log or update a status. delay is in milliseconds. It is not called after the final failure.

Errors

When the retries run out, or shouldRetry returns false, retry rejects with the error from the last attempt, unchanged. Your catch block sees the same error fn threw, so instanceof checks keep working. If the signal aborts, it rejects with signal.reason.

Recipes

Handle HTTP 429

A 429 response means the server wants you to slow down, and often says how long to wait in a Retry-After header. Throw an error that carries the response, then let shouldRetry retry only 429s and return the server's wait.

With no Retry-After header, the function returns true and the normal backoff applies. Add || status >= 500 to the status check if you also want to retry server errors.

Abort with AbortSignal

Pass a signal to stop retrying when the user cancels or the page goes away. Hand ctx.signal to fetch so an in-flight request stops too.

To give the whole operation a time budget, pass a timeout signal. Attempts and waits together stop after ten seconds, and the rejection reason is a TimeoutError.

Custom retry predicates

By default every error is retried, including ones that will never succeed, like a bad request. Use shouldRetry to retry only what is worth retrying.

The predicate also gets the attempt number, so you can allow different errors a different number of tries.
