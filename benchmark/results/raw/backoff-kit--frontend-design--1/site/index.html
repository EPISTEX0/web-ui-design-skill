backoff-kit

A small TypeScript library for retrying async calls with exponential backoff and jitter. Zero dependencies, works in Node 18+, Deno, Bun and browsers.

Install

npm install backoff-kit
pnpm add backoff-kit
yarn add backoff-kit
bun add backoff-kit

Types are bundled; no @types package is needed. The package ships ESM and CommonJS builds.

Quick start

Wrap any function that returns a promise. If it rejects, retry waits and calls it again, up to the configured number of retries.

import { retry } from "backoff-kit";

const user = await retry(
  async (attempt) => {
    const res = await fetch("https://api.example.com/users/42");
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();
  },
  { retries: 4, minDelay: 200, maxDelay: 5_000 },
);

With these settings a failing call runs at most 5 times (1 initial attempt + 4 retries), waiting roughly 200 ms, 400 ms, 800 ms and 1.6 s between attempts, each randomized by jitter. If every attempt fails, the last error is thrown.

retry(fn, options)

function retry<T>(
  fn: (attempt: number) => Promise<T> | T,
  options?: RetryOptions,
): Promise<T>;
ParameterDescription
fnThe operation to run. Receives the attempt number, starting at 0 for the first call. May be sync or async; a synchronous throw counts as a rejection.
optionsOptional. See Options. Every field has a default.

Returns a promise that resolves with the first successful result of fn, or rejects with the last error once retries are exhausted, shouldRetry returns false, or the signal aborts.

Options

interface RetryOptions {
  retries?: number;                 // default 3
  minDelay?: number;                // default 100 (ms)
  maxDelay?: number;                // default 30_000 (ms)
  factor?: number;                  // default 2
  jitter?: "full" | "equal" | "none"; // default "full"
  signal?: AbortSignal;
  shouldRetry?: (error: unknown, attempt: number) => boolean | Promise<boolean>;
  retryAfter?: (error: unknown, attempt: number) => number | undefined;
  onRetry?: (info: { error: unknown; attempt: number; delay: number }) => void;
}

retries

number · default 3

Maximum number of retries after the first attempt. 0 disables retrying; Infinity retries until success, a non-retryable error, or abort.

minDelay

number (ms) · default 100

Base delay before the first retry. The un-jittered delay before retry n (starting at 0) is minDelay × factorn.

maxDelay

number (ms) · default 30000

Upper bound on any single wait. The exponential value is capped here before jitter is applied.

factor

number · default 2

Multiplier applied to the delay after each failed attempt. Use 1 for a constant delay.

jitter

"full" | "equal" | "none" · default "full"

Randomization applied to each wait so many clients don't retry in lockstep.

  • "full": random value in [0, cap]. Best at spreading load.
  • "equal": cap/2 plus a random value in [0, cap/2]. Keeps a guaranteed minimum wait.
  • "none": exactly cap. Deterministic; useful in tests.

signal

AbortSignal · optional

Cancels the retry loop, including any wait in progress. The returned promise rejects with the signal's reason. See the recipe.

shouldRetry

(error, attempt) => boolean | Promise<boolean> · default: always retry

Called after each failure. Return false to stop immediately and reject with that error. attempt is the 0-based number of the attempt that just failed.

retryAfter

(error, attempt) => number | undefined · optional

Return a delay in milliseconds to override the computed backoff for this retry, for example from a Retry-After header. Return undefined to use the normal backoff. The value is still capped by maxDelay and is not jittered.

onRetry

({ error, attempt, delay }) => void · optional

Called just before each wait, with the delay in ms about to be used. Handy for logging and metrics. Exceptions thrown here are ignored.

How delays are computed

For retry number n (0-based): cap = min(maxDelay, minDelay × factorn), then jitter is applied to cap. Try it:

Solid bar = sampled wait. Shaded area = cap before jitter.

Errors

When retries are exhausted, retry rejects with the original error from the last attempt, unwrapped, so instanceof checks keep working. When aborted, it rejects with signal.reason (a DOMException named AbortError by default).

Recipe: HTTP 429 handling

Retry on 429 and transient 5xx, and honor the server's Retry-After header when present. Other 4xx errors are our bug, not a transient fault, so they fail fast.

import { retry } from "backoff-kit";

class HttpError extends Error {
  constructor(readonly status: number, readonly headers: Headers) {
    super(`HTTP ${status}`);
  }
}

// Retry-After is either seconds ("120") or an HTTP date.
function parseRetryAfter(value: string | null): number | undefined {
  if (!value) return undefined;
  const seconds = Number(value);
  if (Number.isFinite(seconds)) return seconds * 1000;
  const date = Date.parse(value);
  return Number.isNaN(date) ? undefined : Math.max(0, date - Date.now());
}

const data = await retry(
  async () => {
    const res = await fetch("https://api.example.com/search?q=retry");
    if (!res.ok) throw new HttpError(res.status, res.headers);
    return res.json();
  },
  {
    retries: 5,
    minDelay: 500,
    maxDelay: 60_000,
    shouldRetry: (err) =>
      err instanceof HttpError && (err.status === 429 || err.status >= 500),
    retryAfter: (err) =>
      err instanceof HttpError ? parseRetryAfter(err.headers.get("retry-after")) : undefined,
    onRetry: ({ attempt, delay }) =>
      console.warn(`retry #${attempt + 1} in ${Math.round(delay)} ms`),
  },
);
Network failures from fetch surface as TypeError. If you want to retry those too, add || err instanceof TypeError to the predicate.

Recipe: aborting with AbortSignal

Pass a signal to stop retrying, for example on a user cancel or an overall deadline. Aborting also interrupts the current wait, so you don't sit out a 30-second delay. Pass the same signal to fetch to cancel the in-flight request too.

import { retry } from "backoff-kit";

const controller = new AbortController();
cancelButton.onclick = () => controller.abort();

try {
  const report = await retry(
    async () => {
      const res = await fetch("/api/report", { signal: controller.signal });
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      return res.json();
    },
    { retries: 10, signal: controller.signal },
  );
  render(report);
} catch (err) {
  if (controller.signal.aborted) return; // user cancelled, not a failure
  throw err;
}

For an overall time budget, combine it with AbortSignal.timeout:

await retry(callFlakyService, {
  retries: Infinity,
  signal: AbortSignal.timeout(20_000), // give up after 20 s total
});

Recipe: custom retry predicates

shouldRetry can be async and can use the attempt number, so you can encode any policy: error codes, attempt-dependent rules, or consulting a circuit breaker.

import { retry } from "backoff-kit";

const TRANSIENT = new Set(["ECONNRESET", "ETIMEDOUT", "EAI_AGAIN"]);

await retry(() => db.query("select 1"), {
  retries: 6,
  shouldRetry: async (err, attempt) => {
    const code = (err as NodeJS.ErrnoException).code;
    if (code && TRANSIENT.has(code)) return true;       // network blip
    if (code === "SERIALIZATION_FAILURE") return attempt < 2; // only twice
    return false;                                           // anything else: fail fast
  },
});

Returning false rejects immediately with the error that was passed in, without waiting.
