backoff-kit

Retry async calls with exponential backoff and jitter. One function, zero dependencies, written in TypeScript.

  • TypeScript types included
  • ESM + CJS
  • No dependencies
  • Node 18+ and browsers

Install

npm
npm install backoff-kit
pnpm / yarn / bun
pnpm add backoff-kit
yarn add backoff-kit
bun add backoff-kit

Quick start

Wrap the call you want retried in a function and pass it to retry. The function runs again whenever it throws or rejects, after a growing, randomised delay.

TypeScript
import { retry } from "backoff-kit";

const user = await retry(
  () => fetch("https://api.example.com/users/42").then((r) => r.json()),
  { retries: 5, minDelay: 200 }
);

With these settings, a failing call is retried up to 5 times. The waits grow from about 200 ms and roughly double each time.

API: retry(fn, options?)

Signature
function retry<T>(
  fn: (attempt: number) => Promise<T> | T,
  options?: RetryOptions
): Promise<T>;

fn receives the attempt number, starting at 0 for the first try. retry resolves with the first successful result of fn. If every attempt fails, or retrying is stopped, it rejects.

Options

OptionTypeDefaultDescription
retriesnumber3Retries after the first attempt. retries: 3 means up to 4 calls in total.
minDelaynumber (ms)100Base delay before the first retry.
maxDelaynumber (ms)30000Upper bound for any single delay, applied before jitter.
factornumber2Multiplier per attempt. The delay ceiling for retry n is min(maxDelay, minDelay × factorn).
jitter"full" | "equal" | "none""full"full picks uniformly from 0 to the ceiling. equal picks from half the ceiling to the ceiling. none waits exactly the ceiling.
shouldRetry(error, attempt) => boolean | Promise<boolean>retry every errorReturn false to stop at once and reject with that error.
onRetry(error, attempt, delay) => voidnoneCalled before each wait. Use it for logging or metrics.
signalAbortSignalnoneAborting cancels any pending wait and rejects with the signal's reason.

Delay curve

Change the options to see the wait before each retry. The line is the ceiling and the shaded band is where jitter can land.

Errors and return value

When attempts run out, retry rejects with the error from the last attempt, unchanged. Nothing is wrapped, so instanceof checks and custom error fields keep working.

Recipes

Handle HTTP 429 and honour Retry-After

Retry rate-limited and transient server responses, and give up on other 4xx errors. When the server sends Retry-After, wait at least that long before the next attempt.

TypeScript
import { retry } from "backoff-kit";

class HttpError extends Error {
  constructor(public status: number, public retryAfterMs?: number) {
    super(`HTTP ${status}`);
  }
}

async function getJson(url: string) {
  return retry(
    async () => {
      const res = await fetch(url);
      if (!res.ok) {
        const secs = Number(res.headers.get("retry-after"));
        throw new HttpError(res.status, secs > 0 ? secs * 1000 : undefined);
      }
      return res.json();
    },
    {
      retries: 5,
      shouldRetry: async (err) => {
        if (!(err instanceof HttpError)) return true;      // network error
        if (err.retryAfterMs) await sleep(err.retryAfterMs); // honour the server
        return err.status === 429 || err.status >= 500;
      },
    }
  );
}

const sleep = (ms: number) => new Promise((r) => setTimeout(r, ms));

shouldRetry may be async, so waiting inside it delays the next attempt. The backoff delay still applies after it, which keeps retries spaced out.

Abort with AbortSignal

Pass a signal to stop retrying when the user navigates away, a request times out or the process shuts down. A pending wait ends right away.

TypeScript
const controller = new AbortController();

// Give up after 10 seconds, whatever the attempt count.
const timeout = AbortSignal.timeout(10_000);
const signal = AbortSignal.any([controller.signal, timeout]);

try {
  await retry(() => syncOrders({ signal }), { retries: 8, signal });
} catch (err) {
  if (signal.aborted) {
    console.log("stopped:", signal.reason);
  } else {
    throw err;
  }
}

// Elsewhere, e.g. on component unmount:
controller.abort();

Pass the same signal to the work inside fn as well, so an in-flight request is cancelled and not only the waiting.

Custom retry predicates

Use shouldRetry to separate errors worth retrying from those that never will succeed, such as validation failures or auth errors. Use onRetry to see what is happening.

TypeScript
const TRANSIENT = new Set(["ECONNRESET", "ETIMEDOUT", "EAI_AGAIN"]);

await retry(() => db.query(sql), {
  retries: 4,
  minDelay: 250,
  jitter: "equal",
  shouldRetry: (err, attempt) => {
    if (attempt >= 2 && err instanceof SlowQueryError) return false;
    return TRANSIENT.has((err as NodeJS.ErrnoException).code ?? "");
  },
  onRetry: (err, attempt, delay) =>
    console.warn(`attempt ${attempt} failed (${err.message}); retrying in ${delay}ms`),
});
