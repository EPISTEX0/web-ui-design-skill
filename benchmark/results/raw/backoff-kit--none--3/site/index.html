backoff-kit

Retry async calls with exponential backoff and jitter. Small, dependency-free, written in TypeScript.

TypeScript types included Zero dependencies Works in Node, Deno, Bun and browsers Open source

Install

npm install backoff-kit

The package ships ESM and CommonJS builds with bundled type declarations. Nothing else to install.

Quick start

Wrap any function that returns a promise. retry calls it, and if it throws or rejects, waits and calls it again, up to the configured number of retries.

import { retry } from "backoff-kit";

const user = await retry(
  async () => {
    const res = await fetch("https://api.example.com/users/42");
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();
  },
  { retries: 4, minDelay: 200 }
);

With no options, retry makes up to 6 attempts (1 initial + 5 retries), waiting roughly 100 ms, 200 ms, 400 ms… between them, with full jitter, capped at 30 s.

retry(fn, options)

function retry<T>(
  fn: (attempt: number) => T | PromiseLike<T>,
  options?: RetryOptions
): Promise<T>;
ParameterDescription
fnThe operation to run. It receives the attempt number, starting at 0 for the first call. May be sync or async.
optionsOptional RetryOptions. Every field is optional.
returnsA promise that resolves with the value from the first successful call to fn, or rejects with the last error once retries are exhausted, shouldRetry declines, or the signal aborts.

retries

number · default 5

Maximum number of retries after the first attempt. retries: 3 means at most 4 calls to fn. Use 0 to disable retrying, or Infinity to retry until success, a declined shouldRetry, or an abort.

minDelay

number, milliseconds · default 100

The base delay before the first retry, before jitter. Later delays grow from this value by factor.

maxDelay

number, milliseconds · default 30000

Upper bound for any single delay. The exponential curve is capped here before jitter is applied.

factor

number · default 2

Multiplier applied for each successive retry. 2 doubles the delay each time; 1 gives a constant delay.

jitter

"full" | "equal" | "none" · default "full"

Randomisation that stops many clients from retrying in lockstep.

  • "full": a random delay between 0 and the capped exponential value. Best at spreading load.
  • "equal": half the value is fixed, half is random. Keeps a guaranteed minimum wait.
  • "none": the exact exponential value. Predictable, useful in tests.

shouldRetry

(error: unknown, attempt: number) => boolean | number | Promise<boolean | number>

Called after each failure to decide whether to try again. Return false to stop and reject with that error, or true to continue with the computed delay. Returning a number retries after exactly that many milliseconds, bypassing the backoff calculation (and maxDelay). attempt is the zero-based index of the attempt that just failed. Not called once retries is exhausted.

onRetry

(error: unknown, attempt: number, delay: number) => void

Called just before waiting, once per scheduled retry. Use it for logging or metrics. delay is the number of milliseconds about to be waited. Errors thrown here propagate and abort the retry loop.

signal

AbortSignal

Cancels the retry loop. If the signal aborts while waiting, the wait ends immediately and the promise rejects with signal.reason. If it is already aborted, fn is never called. An in-flight call to fn is not interrupted by retry; pass the same signal to fetch (or similar) to cancel that too. See the recipe.

How delays are computed

For retry number n (starting at 0):

const capped = Math.min(maxDelay, minDelay * factor ** n);

// jitter: "none"  → capped
// jitter: "full"  → random(0, capped)
// jitter: "equal" → capped / 2 + random(0, capped / 2)

Try it. The light bar is the cap for each retry; the solid bar is one sampled delay.

Errors

When retrying stops, retry rejects with the original error from the last attempt, unchanged, so existing catch blocks and instanceof checks keep working. If the signal aborts, it rejects with signal.reason (a DOMException named AbortError by default).

Recipes

HTTP 429 handling

Retry on 429 and transient 5xx responses, and honour the server's Retry-After header by returning a number from shouldRetry.

import { retry } from "backoff-kit";

class HttpError extends Error {
  constructor(public status: number, public retryAfter?: string | null) {
    super(`HTTP ${status}`);
  }
}

function retryAfterMs(value?: string | null): number | undefined {
  if (!value) return;
  const secs = Number(value);
  if (!Number.isNaN(secs)) return secs * 1000;
  const date = Date.parse(value);          // HTTP-date form
  return Number.isNaN(date) ? undefined : Math.max(0, date - Date.now());
}

const data = await retry(
  async () => {
    const res = await fetch("https://api.example.com/items");
    if (!res.ok) throw new HttpError(res.status, res.headers.get("retry-after"));
    return res.json();
  },
  {
    retries: 6,
    shouldRetry: (err) => {
      if (!(err instanceof HttpError)) return true;      // network failure
      if (err.status === 429) {
        const wait = retryAfterMs(err.retryAfter);
        return wait ?? true;                           // header wins, else backoff
      }
      return err.status >= 500;                          // retry 5xx, not 4xx
    },
    onRetry: (err, attempt, delay) =>
      console.warn(`retry #${attempt + 1} in ${Math.round(delay)}ms`, err),
  }
);

Cap overly long server hints yourself (for example Math.min(wait, 60_000)) since numeric returns bypass maxDelay.

Aborting with AbortSignal

Pass one signal to both retry and the underlying request so cancelling stops the wait and the in-flight call. Combine with AbortSignal.timeout for an overall deadline.

const controller = new AbortController();

// Give up after 10 seconds in total, or when the user clicks Cancel.
const signal = AbortSignal.any([
  controller.signal,
  AbortSignal.timeout(10_000),
]);

cancelButton.addEventListener("click", () => controller.abort());

try {
  const res = await retry(
    () => fetch("/api/report", { signal }),
    { retries: Infinity, signal }
  );
  render(await res.json());
} catch (err) {
  if ((err as Error).name === "AbortError" || (err as Error).name === "TimeoutError") {
    // cancelled or timed out: not a real failure
  } else throw err;
}

AbortSignal.any and AbortSignal.timeout need Node 20+ or a current browser.

Custom retry predicates

Only retry errors that are plausibly transient. Retrying a validation error or a 404 just wastes time.

const TRANSIENT_CODES = new Set(["ECONNRESET", "ETIMEDOUT", "EAI_AGAIN", "ECONNREFUSED"]);

const rows = await retry(() => db.query(sql), {
  retries: 3,
  jitter: "equal",
  shouldRetry: async (err, attempt) => {
    const code = (err as { code?: string }).code;
    if (code && TRANSIENT_CODES.has(code)) return true;
    if (code === "40001") return attempt < 2;       // serialization failure: only twice
    return false;                              // everything else fails fast
  },
});

Predicates may be async, so they can also consult a circuit breaker or feature flag before allowing another attempt.
