backoff-kit

Retry async calls with exponential backoff and jitter. One function, a handful of options, full type inference.

Install

npm install backoff-kit

Also works with pnpm add backoff-kit and yarn add backoff-kit. It ships its own type definitions, so there is nothing extra to install for TypeScript.

Quick start

Wrap any function that returns a promise. If it rejects, retry waits and calls it again, up to retries more times. The resolved value keeps its type.

ts
import { retry } from "backoff-kit";

const user = await retry(
  () => fetchUser("42"),   // Promise<User>
  { retries: 5, minDelay: 200 },
);
// user: User

With these settings a failing call is retried after roughly 200 ms, 400 ms, 800 ms, 1.6 s and 3.2 s (each randomized by jitter), then the last error is thrown.

retry(fn, options)

function retry<T>(
  fn: (attempt: number) => Promise<T> | T,
  options?: RetryOptions,
): Promise<T>;

fn receives the attempt number, starting at 0 for the first call. retry resolves with the first successful result. It rejects with the last error once retries are exhausted, when shouldRetry returns false, or when the signal aborts.

retriesnumber · default 3

Maximum number of re-tries after the first call, so retries: 3 means up to 4 calls in total. Use 0 to disable retrying.

minDelaynumber (ms) · default 100

The base delay before the first retry. Later delays grow from this value.

maxDelaynumber (ms) · default 30000

Upper bound for any single wait. The exponential curve is capped here before jitter is applied, so a long retry chain never sleeps longer than this.

factornumber · default 2

Growth multiplier per attempt. 2 doubles the ceiling each time; 1 gives a constant delay.

jitter"full" | "equal" | "none" · default "full"

Randomizes each wait so many clients that failed together don't all retry together.

  • "full": wait a random time between 0 and the ceiling.
  • "equal": wait half the ceiling plus a random time up to the other half.
  • "none": wait exactly the ceiling. Handy in tests; avoid it in production fleets.

shouldRetry(error, attempt) => boolean · default retry all

Called after each failure. Return false to stop immediately and reject with that error. May be async. attempt is the zero-based index of the call that just failed. See custom predicates.

onRetry(error, attempt, delay) => void

Called just before sleeping, only when a retry will actually happen. delay is the chosen wait in milliseconds. Use it for logging and metrics.

signalAbortSignal

Cancels the operation. Aborting during a wait ends the wait immediately and rejects with the signal's reason. The signal is not passed to fn automatically; pass it yourself if the call supports it. See aborting.

How delays are computed

Before retry n (counting from 0), the ceiling is:

ceiling = min(maxDelay, minDelay * factor ** n)

full  : delay = random(0, ceiling)
equal : delay = ceiling / 2 + random(0, ceiling / 2)
none  : delay = ceiling

Errors

When retries run out, retry rejects with the last error thrown by fn, unchanged, so your existing catch blocks and instanceof checks keep working. If the signal aborts, it rejects with signal.reason (a DOMException named AbortError by default).

Recipe: HTTP 429 handling

fetch doesn't reject on 4xx or 5xx responses, so turn them into errors, then retry only the ones worth retrying: rate limits (429) and transient server failures.

ts
import { retry } from "backoff-kit";

class HttpError extends Error {
  constructor(public status: number, public res: Response) {
    super(`HTTP ${status}`);
  }
}

const RETRYABLE = new Set([429, 502, 503, 504]);

async function getJson<T>(url: string): Promise<T> {
  return retry(
    async () => {
      const res = await fetch(url);
      if (!res.ok) throw new HttpError(res.status, res);
      return (await res.json()) as T;
    },
    {
      retries: 5,
      minDelay: 500,
      jitter: "full",
      // Network failures (TypeError) and retryable statuses only.
      shouldRetry: (err) =>
        err instanceof TypeError ||
        (err instanceof HttpError && RETRYABLE.has(err.status)),
      onRetry: (err, attempt, delay) =>
        console.warn(`retry #${attempt + 1} in ${Math.round(delay)}ms`, err),
    },
  );
}
Retry-After. If the server sends a Retry-After header, the exponential schedule doesn't know about it. For strict APIs, raise minDelay to at least that value, or wait inside fn before throwing.

Recipe: aborting with AbortSignal

Pass a signal to stop both the waits between attempts and, if you forward it, the in-flight request. This works for user cancellation and overall timeouts.

ts
const controller = new AbortController();
cancelButton.onclick = () => controller.abort();

try {
  const data = await retry(
    () => fetch("/api/report", { signal: controller.signal }).then((r) => r.json()),
    { retries: 8, signal: controller.signal },
  );
  render(data);
} catch (err) {
  if ((err as Error).name === "AbortError") return; // user cancelled
  throw err;
}

For an overall deadline across all attempts, use a timeout signal:

ts
const signal = AbortSignal.timeout(15_000); // give up after 15s in total

await retry(() => callFlakyService({ signal }), { retries: 10, signal });
Make your shouldRetry return false for AbortErrors raised by your own request so a cancelled fetch isn't treated as a transient failure: (err) => (err as Error).name !== "AbortError".

Recipe: custom retry predicates

shouldRetry decides, per error, whether another attempt is worthwhile. Fail fast on errors that will never succeed, such as validation errors or 401s.

ts
// 1. Retry only specific error codes
const TRANSIENT = new Set(["ECONNRESET", "ETIMEDOUT", "EAI_AGAIN"]);

await retry(queryDatabase, {
  shouldRetry: (err) => TRANSIENT.has((err as NodeJS.ErrnoException).code ?? ""),
});

// 2. Use the attempt number: be pickier as time goes on
await retry(sendEmail, {
  retries: 6,
  shouldRetry: (err, attempt) => attempt < 2 || isServerError(err),
});

// 3. Async predicate: consult a circuit breaker or health check
await retry(callPaymentApi, {
  shouldRetry: async (err) => (await breaker.isOpen()) === false,
});
