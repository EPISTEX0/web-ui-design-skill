backoff-kit

A small TypeScript library for retrying async calls with exponential backoff and jitter. One function, no dependencies.

  • Zero dependencies
  • Typed end to end
  • Cancellable with AbortSignal
  • Works in Node 18+, browsers and edge runtimes

Install

npm
npm install backoff-kit
pnpm / yarn
pnpm add backoff-kit
yarn add backoff-kit

Types are bundled; there is nothing extra to install.

Quick start

Wrap any function that returns a promise. If it rejects, retry waits and calls it again, up to retries more times. The first success resolves; if every attempt fails, the last error is thrown.

ts
import { retry } from "backoff-kit";

const user = await retry(
  async ({ attempt }) => {
    const res = await fetch("https://api.example.com/users/42");
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();
  },
  { retries: 4, minDelay: 200, jitter: "full" },
);

With these settings a failing call is attempted up to 5 times in total, waiting somewhere between 0 and 200 ms, then 0 and 400 ms, and so on between attempts.

API

signature
function retry<T>(
  fn: (ctx: { attempt: number; signal?: AbortSignal }) => Promise<T> | T,
  options?: RetryOptions,
): Promise<T>;

fn receives a context object. attempt starts at 1 for the first call. signal is the same signal you passed in options, so you can forward it to fetch. Synchronous throws are treated like rejections.

Options

Every option is optional.

retries number default 5

Maximum number of retries after the first attempt. retries: 0 calls fn once and never retries. The total number of calls is at most retries + 1.

minDelay number (ms) default 100

The base delay before the first retry. Later delays grow from this value by factor.

maxDelay number (ms) default 30000

Upper bound for the exponential delay, applied before jitter. Keeps long retry chains from waiting minutes between attempts.

factor number default 2

Growth multiplier per attempt. 2 doubles the delay each time; 1 gives a constant delay.

jitter "full" | "equal" | "none" default "full"

Randomizes each delay so many clients that failed together do not retry together.

  • "full": a random value between 0 and the computed delay. Best spread; the default.
  • "equal": half the computed delay plus a random value up to the other half. Guarantees some minimum wait.
  • "none": exactly the computed delay. Predictable, useful in tests.

signal AbortSignal default none

Cancels the whole operation. If the signal aborts during a wait, the wait ends immediately; if it aborts between attempts, no further attempt starts. The returned promise rejects with signal.reason. See the abort recipe.

shouldRetry (error: unknown, attempt: number) => boolean | Promise<boolean> default always true

Called after each failure. Return false to stop at once and reject with that error. attempt is the number of the attempt that just failed. Retries remaining are still capped by retries.

onRetry (error: unknown, attempt: number, delay: number) => void default none

Called just before waiting, once per scheduled retry, with the chosen delay in milliseconds. Use it for logging and metrics. It is not called when the final attempt fails.

How delays are computed

Before retry n (starting at 1) the base delay is min(maxDelay, minDelay × factor^(n−1)). Jitter is then applied to that value. Try the settings below to see the range each wait can fall in.

Recipes

HTTP 429 handling

Retry on 429 and transient 5xx responses, and respect the server's Retry-After header when present. Throw an error that carries the status so shouldRetry can decide, and never retry other 4xx errors.

ts
import { retry } from "backoff-kit";

class HttpError extends Error {
  constructor(readonly status: number, readonly retryAfterMs?: number) {
    super(`HTTP ${status}`);
  }
}

const sleep = (ms: number, signal?: AbortSignal) =>
  new Promise<void>((resolve, reject) => {
    const t = setTimeout(resolve, ms);
    signal?.addEventListener("abort", () => { clearTimeout(t); reject(signal.reason); }, { once: true });
  });

async function getJson(url: string) {
  return retry(
    async ({ signal }) => {
      const res = await fetch(url, { signal });
      if (res.ok) return res.json();

      // Retry-After is seconds (or an HTTP date; seconds shown here).
      const header = Number(res.headers.get("retry-after"));
      const wait = Number.isFinite(header) && header > 0 ? header * 1000 : undefined;
      if (res.status === 429 && wait) await sleep(Math.min(wait, 30_000), signal);
      throw new HttpError(res.status, wait);
    },
    {
      retries: 5,
      minDelay: 500,
      shouldRetry: (err) =>
        err instanceof HttpError && (err.status === 429 || err.status >= 500),
      onRetry: (err, attempt, delay) =>
        console.warn(`attempt ${attempt} failed (${(err as Error).message}); retrying in ${delay} ms`),
    },
  );
}

The server's Retry-After wait happens inside fn, then the normal backoff delay is added on top. That is deliberately conservative: it never retries sooner than the server asked.

Aborting with AbortSignal

Pass a signal to cancel pending waits and stop further attempts. Forward the same signal to fetch so an in-flight request is cancelled too.

ts
import { retry } from "backoff-kit";

// Give up after 10 seconds in total.
const signal = AbortSignal.timeout(10_000);

try {
  const data = await retry(
    ({ signal }) => fetch("/api/report", { signal }).then((r) => r.json()),
    { retries: 8, signal },
  );
} catch (err) {
  if (signal.aborted) {
    console.log("Cancelled:", signal.reason); // TimeoutError or your own reason
  } else {
    throw err; // the last error from fn
  }
}

// Or cancel on demand, for example when a component unmounts:
const controller = new AbortController();
const pending = retry(callApi, { signal: controller.signal });
controller.abort(new Error("user navigated away"));

Custom retry predicates

shouldRetry can be async and can use the attempt number. This example retries only network-level failures and database deadlocks, and gives up on a slow-failing call after three attempts.

ts
import { retry } from "backoff-kit";

const TRANSIENT = new Set(["ECONNRESET", "ETIMEDOUT", "EAI_AGAIN"]);

await retry(() => db.transaction(work), {
  retries: 6,
  jitter: "equal",
  shouldRetry: async (err, attempt) => {
    const code = (err as { code?: string }).code;
    if (code === "40P01") return true;           // Postgres deadlock
    if (code && TRANSIENT.has(code)) return attempt < 3; // network: only a couple of tries
    return false;                                // validation, auth, bugs: fail fast
  },
});

Return false for errors that will not get better by waiting, such as validation failures or 401 responses. Retrying them only delays the real error.
